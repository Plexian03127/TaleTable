# Tale Table – 데이터 저장 방법

Tale Table은 **서버 없이 플레이어의 웹 브라우저 안에 데이터를 저장**합니다.
플레이 중에는 모든 게임 상태를 메모리의 상태 객체 `S` 하나에 담고, 정해진 순간에만 JSON 문자열로 바꿔 브라우저 저장소에 씁니다.
AI(Claude·Gemini)에는 매 턴 필요한 상황만 프롬프트로 보내고, AI 쪽에는 아무것도 저장하지 않습니다.

## 저장 데이터 목록

| 데이터 | 저장 위치 | 키 이름 | 내용 | 유지 기간 |
|---|---|---|---|---|
| 진행 중인 모험 | localStorage | `tt_save_v1` | 게임 상태 전체, 화면 기록, 저장 시각, 요약 문구 | 엔딩을 보거나 직접 삭제할 때까지 (1칸) |
| 엔딩 수집 기록 | localStorage | `trpg_end` | 달성한 엔딩 이름 목록 (예: `["classic","peace"]`) | 브라우저 데이터를 지울 때까지 |
| 개발자 모드 설정 | sessionStorage | `tt_dev` | 개발자 모드 켜짐 여부, 고정한 AI 모델 | 탭을 닫을 때까지 |

- 저장 칸은 1개입니다. 새로 저장하면 이전 저장을 덮어씁니다.
- 예전 버전의 '플레이어 API 연결'이 남긴 값(`tt_ai_prov`, `tt_ai_model`, `tt_ai_key`)은 게임을 열 때 자동으로 지웁니다.

## 저장 시점

| 상황 | 저장하는 것 | 화면 알림 |
|---|---|---|
| 자동 저장 | 3턴을 끝낼 때마다(3·6·9턴…) 진행 중인 모험 | 💾 자동 저장 (3턴) |
| 저장하고 나가기 버튼 | 확인 후 진행 중인 모험을 저장하고 타이틀로 이동 | 💾 저장했습니다 |
| 엔딩 도달 | 처음 본 엔딩 이름을 엔딩 수집 기록에 추가 | (새 엔딩!) |

저장하지 않는 경우: 게임 시작 직후, 이어하기 직후의 같은 턴, AI가 장면을 쓰는 중, 엔딩을 본 뒤(남아 있던 저장도 자동 삭제).

## 불러오기와 삭제

1. 저장된 모험이 있으면 타이틀에 **이어하기** 버튼이 나타납니다.
2. 이어하기를 누르면 저장 요약(세계관 · 직업 · 장소 · 턴 · HP)과 저장 시각을 보여 주는 확인 창이 뜹니다.
3. **이어하기** → 저장된 문자열을 읽어 게임 상태와 화면 기록을 되돌립니다.
4. **🗑 저장된 모험 삭제하기** → 한 번 더 확인한 뒤 저장값을 지웁니다. 되돌릴 수 없습니다.

저장값이 깨졌거나 형식 버전(`v`)이 다르면 없는 것으로 보고 "저장 데이터를 불러오지 못했습니다"를 띄웁니다.

## 저장 데이터 구조

```json
{
  "v": 1,
  "t": 1763625600000,
  "auto": true,
  "pickW": 0,
  "pick": 1,
  "S": { "...": "게임 상태" },
  "log": "<p>화면에 표시된 이야기 기록</p>",
  "sum": "🏰 어둠의 던전 · 🗡️ 도적 · 무너진 회랑 · 7턴 · HP 12/18"
}
```

| 항목 | 뜻 |
|---|---|
| `v` | 저장 형식 버전. 1이 아니면 불러오지 않음 |
| `t`, `auto` | 저장 시각, 자동 저장 여부 |
| `pickW`, `pick` | 선택한 세계관과 직업 번호 |
| `S` | 게임 상태 전체 |
| `log` | 이야기 기록 화면. 용량을 줄이려고 그림 데이터는 빼고 어느 그림인지만 남김 |
| `sum` | 이어하기 창에 보여 줄 한 줄 요약 |

게임 상태 `S`의 주요 항목

| 묶음 | 항목 |
|---|---|
| 캐릭터 | 능력치(`st`), HP(`hp`, `mhp`), 소지품(`items`), 장착(`equip`) |
| 위치·전투 | 현재 장소(`loc`), 장소별 남은 적 HP(`hpE`), 이미 탐색한 장소(`found`), 보스 등장 여부(`boss`) |
| NPC | NPC별 신뢰도(`tr`), 숨은 사연 개방(`sec`), 이름을 알게 된 NPC(`known`), 대화 횟수(`talks`) |
| 의뢰·갈림길 | 의뢰 상태(`q`, `qAvail`, `dec`), 흥정(`hagg`), 절도·대화 거부(`stolen`, `blocked`), 보스 처리 방식(`how`) |
| 진행 | 턴 수(`turn`), 끝났는지(`over`), AI에 보낼 최근 이야기 요약(`hist`) |

## 설계 이유와 한계

브라우저 저장을 고른 이유
- 서버가 필요 없어 HTML 파일 하나로 플레이와 저장이 됩니다.
- 회원가입·로그인 없이 바로 플레이할 수 있습니다.
- 저장 데이터는 플레이어 기기에만 있고 다른 곳으로 전송되지 않습니다.
- HP·신뢰도·의뢰 상태는 AI가 아니라 게임 코드가 들고 있어서, AI 모델이 바뀌거나 연결이 끊겨도 저장된 진행은 그대로입니다.

| 한계 | 설명 |
|---|---|
| 기기·브라우저별 분리 | PC에서 저장한 모험을 휴대폰에서 이어할 수 없고, 엔딩 수집도 따로 집계됩니다. |
| 사라질 수 있음 | 브라우저 데이터 삭제, 시크릿 창 종료, 저장 공간 차단 시 저장되지 않거나 사라집니다. 차단된 경우 "저장에 실패했습니다"를 알립니다. |
| 저장 칸 1개 | 여러 모험을 동시에 보관할 수 없습니다. MVP 범위에서 일부러 뺀 기능입니다. |
| 수정 가능 | 저장값이 암호화되지 않아 개발자 도구로 고칠 수 있습니다. 1인용 게임이라 큰 문제는 아닙니다. |

기기 간 이어하기가 필요해지면 저장 서버와 계정을 두는 방식으로 바꿔야 합니다.
